# 元书皮肤：笔画键盘顶部「符号快捷栏」配置指引

> 对标讯飞笔画键盘（bihuakey.ini）的符号快捷栏：候选栏下方固定一行 `，。？！~…：、`，
> 点按直接上屏标点，避免每次切符号面板打断笔画节奏。
>
> **Rime 侧已全部就绪**，本文件只说明如何在元书皮肤里加这一行键。

## 一、Rime 侧已具备的能力（无需改动）

| 能力 | 位置 | 说明 |
|---|---|---|
| ASCII 标点 → 中文标点 | `punctuator: import_preset: default` | `,`→`，` `.`→`。` `?`→`？` `!`→`！` `:`→`：` `;`→`；` `/`→`、` `~`→`～` |
| 输入中标点顶字 | `punct_commit`（processor） | 输入中有候选时，按标点键先上屏候选再上屏标点 |
| 空输入候选区标点快捷 | `predict_next: mix_punct: true` | 上屏后候选区末尾出现 `，。？！……、：；`，点选直接上屏 |
| 标点 bigram | `ngram.lua`（标点参与上下文） | 上屏 `。` 后自动预测下一句首词 |

## 二、皮肤侧操作步骤（元书）

1. 在元书皮肤编辑器中，找到「笔画」键盘布局；
2. 在候选栏下方或功能键行新增一排（或一行）**文本按键**；
3. 每个按键的「发送内容」填对应 ASCII 键码（元书皮肤按键支持发送键码/文本）：

| 想上屏的符号 | 按键发送 | 说明 |
|---|---|---|
| `，` | `,` | 发送 comma 键 |
| `。` | `.` | 发送 period 键 |
| `？` | `?` | 发送 slash + Shift（或直接字符 `?`） |
| `！` | `!` | 发送 1 + Shift |
| `：` | `:` | 发送 semicolon + Shift |
| `、` | `/` | 发送 slash 键（Rime 默认 `/`→`、`） |
| `……` | `...` | 发送三个句点，或配置 punctuator 映射 |

4. 保存皮肤后重新部署方案即可。

> 提示：如果元书皮肤按键支持直接发送**文本**（而非键码），可以简单地把按键文本设为中文标点本身；
> 此时标点以文本方式提交，同样经过 `punct_commit`/标点 bigram 链路。

## 三、效果

```
笔画键盘
┌─────────────────────────────┐
│ ， 。 ？ ！ …… 、 ： ；     │ ← 符号快捷栏（皮肤新增）
├─────────────────────────────┤
│     候选区（预测/用户词）     │
├─────────────────────────────┤
│  1  2  3  4  5  分词 退格   │
└─────────────────────────────┘
```

- 输入中按 `。` → 当前候选先上屏 + 句号（标点顶字）
- 输入后按 `。` → 句号上屏 → 候选区预测下一句
- 空输入点候选区的 `，。？！` → 直接上屏标点（`mix_punct`）

## 四、常见问题

- **为什么我按 `,` 没反应？** 检查皮肤按键是否真的发送了 `,` 键码（而不是被皮肤拦截成其他功能）。
- **不想显示候选区标点快捷？** 把 `predict_next: mix_punct: false`。
- **想自定义符号？** 修改 `lua/predict_next.lua` 的 `PUNCT_LIST` 表。
